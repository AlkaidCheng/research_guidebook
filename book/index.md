## About this book

Research projects accumulate know-how faster than anyone writes it down: which
generator settings are safe, why a cut sits where it does, how a statistical
test is actually evaluated, what a file format really guarantees. This book
collects that know-how in one place. It is organised by field and by topic,
written in textbook style, and revised as the projects it describes move on.

Each **part** covers one field. Each **chapter** treats one topic within it,
starting from the ideas and ending with the concrete procedures and settings
used in practice. Chapters are self-contained: a reader who needs only the
parton-shower matching conventions should be able to open that chapter, find
the section, and leave.

## How to read it

Sections are numbered within chapters (1.2, 1.2.3), as are equations, figures
and tables, so that any statement can be referred to precisely. Boxed
environments set apart material of a particular kind:

Definition
:   A term fixed for use throughout the book.

Example
:   A worked instance of the surrounding idea.

Remark
:   A caveat, pitfall or side observation worth remembering.

Recipe
:   A concrete, reproducible procedure: commands, settings or a code fragment.

Warning
:   Something that silently gives wrong results.

Citations appear as bracketed numbers and resolve to the reference list at the
end of each chapter. Chapters marked *in preparation* have a settled outline but
unfinished text.
